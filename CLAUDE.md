# CLAUDE.md

Context for working on this repo with Claude Code.

## What this is

A personal Foundry VTT module bundling small PF2e home-game tweaks. Each tweak is one self-contained ES module under `scripts/`, listed in `module.json`'s `esmodules`. Keep new tweaks small, dependency-guarded, and documented in `README.md`.

## Environment

- Foundry VTT **v14**, Pathfinder 2e system. Self-hosted (shell access to the server).
- API docs: https://foundryvtt.com/api (select v14). **Verify anything version-sensitive there** — hook names, document schema fields, and APIs shift between major versions, and training data is often stale.
- Related modules are by reonZ, written in TypeScript and shipped as **minified** bundles. Read their TS source for behavior; don't try to parse the built JS.
  - pf2e-toolbelt — https://github.com/reonZ/pf2e-toolbelt
  - pf2e-hud — https://github.com/reonZ/pf2e-hud
  - PF2e system source — https://github.com/foundryvtt/pf2e (rule elements live under `packs/`)

## Conventions / guardrails

- `MODULE_ID` in scripts must equal `id` in `module.json`. The set-targets socket channel is `module.<id>` and only works if they match and `"socket": true` is in the manifest.
- Prefer hooking public APIs and document flags over copying module internals.
- Mind setting **scope**: `user` settings are per-player; `world`/`client` differ. Per-user features must load on every client.
- Dev loop: edit a script → F5 in-game; edit the manifest → restart the server. Enable the module for the world.
- Git commit attribution trailer: `Agentic - Using Claude <ModelName> <MajorVersion>` — e.g. `Agentic - Using Claude Fable 5` (human-readable model name + major version, never the raw model ID). Also configured in `.claude/settings.json` under `attribution`.

## Current tweaks — load-bearing facts

**`scripts/toolbelt-set-targets.js`** — players push their targets onto a Toolbelt Target Helper card.
- Chat-message flag writes need author/GM permission, so players emit a socket and the **active GM** writes (`game.toolbelt.api.targetHelper.setMessageFlagTargets({}, uuids)`; flag path `flags.pf2e-toolbelt.targetHelper.targets`, an array of Token document UUIDs). A GM must be online.
- v14 chat render hook is `renderChatMessageHTML` (`html` is an `HTMLElement`, not jQuery). Toolbelt renders its buttons asynchronously, so injection is deferred via `requestAnimationFrame` with a bounded retry.
- The injected button must live inside `.dice-result .dice-total` (or Toolbelt's existing `.pf2e-toolbelt-target-buttons` wrapper). That CSS is `position: absolute` anchored to the total bar; injected anywhere else it renders off-card.

**`scripts/pf2e-hud-slots.js`** — raise the Persistent HUD shortcut-slot cap.
- Setting key `pf2e-hud.persistent.slots` (per-user, step 2). Total slots = `18 + slots`. The framework (render loop, template, `grid-auto-flow: column` CSS) is fully dynamic; only the slider's `range.max` caps it. Bump `game.settings.settings.get("pf2e-hud.persistent.slots").range.max` on the `ready` hook, before the settings window is opened.

**`scripts/ap-journal-styles.js`** (+ `styles/ap-journal-styles.css`) — author Metamorphic AP journal blocks from the rich-text editor.
- Adds an "Adventure Path" submenu to the ProseMirror Format dropdown via the `getProseMirrorMenuDropDowns` hook (same mechanism the PF2e system uses; see their `src/scripts/hooks/get-prosemirror-menu-dropdowns.ts` for the canonical pattern).
- **Classes must go in the node's `_preserve` attr** (`attrs: { _preserve: { class: "read-aloud" } }`) — that's Foundry's attribute-capture channel; a bare `class` attr is stripped by the schema on save. Scaffold HTML is parsed with `foundry.prosemirror.dom.parseString` against the editor schema so inserted content round-trips identically to loaded content.
- Metamorphic markup vocabulary (extracted from the real Season of Ghosts packs): `p.read-aloud`; `section.encounter > div.header > (img + h2.split.no-toc > span.keepme×2 + span.link)` — the second `keepme` span is the right-aligned severity; `aside.sidebar` / `aside.float-right`; `section.action` + `ul.traits > li.trait`; `section.advancement-track` with `span.level`; utility classes `no-toc`, `no-indent`, `split`, `keepme`, `float-left/right`. Their CSS is tag-sensitive (`aside.sidebar`, not `.sidebar`) and scoped to their sheet's wrapper class (e.g. `.seasonofghosts-wrapper`), which is why the editor shows nothing — our CSS adds neutral editor-only affordances, all scoped under `.ProseMirror`.
- `reference/` holds the Season of Ghosts basis pack + first AP for inspection; it is not shipped (the release zip packs only `scripts`/`styles`). Journal HTML lives inside LevelDB packs: read with `classic-level` on a **copy** of the pack dir (never the original — opening takes the LOCK); documents sit at `adventure.journal[].pages[].text.content`.

**`scripts/expressions-inserter.js`** — dialog for building inline `@Check`/`@Damage`/`@Template`/`[[/act]]`/`[[/r]]` expressions.
- Param surface verified against system source `src/module/system/text-editor.ts` (`#createCheck`/`#createDamageRoll`): type lists are comma-joined, numeric adjustments get baked into `dc:`, `against:`/`defense:` excludes `dc:`. DC tables mirror `src/module/dc.ts` (PWOL-aware) and are embedded as data.
- Foundry keybindings **don't fire while a text field/editor has focus**, so the in-editor hotkey is a capture-phase `keydown` listener; the registered keybinding covers the out-of-editor (clipboard) case. No double-fire possible.
- EditorViews are captured from `menu.view` in `getProseMirrorMenuDropDowns` (WeakMap keyed on `view.dom`) — there's no reliable public path from a `.ProseMirror` DOM node back to its view. Insertion is `view.state.tr.insertText(...)`; enrichers run on render, so plain text is correct.
- Exports `levelBasedDC`/`partyLevel` etc.; `infiltration-builder.js` imports them (relative ESM imports work between `esmodules` entries).
- AppV2 gotcha (applies to all three builders): `this.element` persists across re-renders — attach delegated listeners to elements *inside* the re-rendered content (the `form`), never to `this.element`, or they stack.

**`scripts/hazard-builder.js`** — GM Core "Building Hazards" tables 2-13…2-16 embedded; creates a Hazard actor.
- Schema verified against `packs/pf2e/hazards`: `attributes.stealth.value` is the **modifier** (DC − 10) for simple *and* complex hazards; min-proficiency rank goes in `stealth.details`. `disable`/`routine`/`reset` are HTML under `system.details`. Strikes are `melee` items (`bonus.value`, `damageRolls` record keyed by random id); trigger/effect is an `action` item with `actionType.value: "reaction"`. `hasHealth: false` suppresses AC/saves/HP.
- `fa.*` is a pf2e-internal alias, not a Foundry global — use `foundry.applications.ux.FormDataExtended` etc.

**`scripts/infiltration-builder.js`** — GM Core Infiltration subsystem → multi-page journal entry.
- Rules basis: crit/success = 2/1 IP, fail/crit-fail = 1/2 AP, +1 AP per round; failure ceiling 2× total IP with thresholds at ~25/50/75/100%. Standard/hard/very-hard DCs = level-based DC +0/+2/+5.
- Preparation-activity compendium IDs were lifted from the system's GM-screen journal pack (`pf2e.actionspf2e`). Condition links resolve IDs at runtime from the `pf2e.conditionitems` index (name match), falling back to plain text.

**`scripts/crafting-formula-search.js`** (+ `styles/crafting-formula-search.css`) — search bar filtering the Crafting tab's Known Formulas list.
- Hook is `renderCharacterSheetPF2e`; the sheet is still AppV1 on pf2e master, so `html` may be jQuery — normalize (`html instanceof HTMLElement ? html : html[0]`) before querying.
- DOM contract (system `tabs/crafting.hbs`): `section.known-formulas > header + ol.formula-list`; rows are `li.formula-item[data-formula-lvl]` with the name in `h4.name`, level headers `li.formula-level-header[data-level]`. Headers hide when no row of their level matches.
- The sheet re-renders wholesale on any actor update, wiping the input — the query is kept in a `WeakMap` keyed by sheet instance and re-applied each render. The system's own inventory search uses Foundry's `SearchFilter` + MiniSearch; a substring filter is deliberate simplification.

**`scripts/compendium-browser-filters.js`** — extra Compendium Browser filters (Equipment: Other Tags + Usage; Feats: Dedication prerequisite).
- The v14 browser filters generically: each result carries an `options: Set<"prefix:value">`, `buildPredicate()` iterates **all** of `filterData.checkboxes` (predicate prefix is `optionPrefix ?? groupKey`), and the Svelte sidebar renders every checkbox group it finds — injected groups need zero UI/filter plumbing.
- Integration point: wrap each tab instance's `loadData` (instances at `game.pf2e.compendiumBrowser.tabs.*`, created in the system's `ready` hook, which runs before module `ready` hooks). Enrichment must happen inside the wrapper: `init()` builds the MiniSearch engine (its `storeFields` already include `options`) and snapshots `defaultFilterData` *after* `loadData`, so text search and filter reset pick up the additions for free.
- Extra data is a supplemental `pack.getIndex({fields})` pass over `browser.loadedPacks(tabName)`, merged by UUID: `system.traits.otherTags`, `system.usage.value` (empty string = carried; kits have no usage), `system.prerequisites.value` (free text; dedications extracted via `/([A-Z][^,;.()]*?)\s+Dedication\b/`). Labels from `CONFIG.PF2E.usages` and `CONFIG.PF2E.other{Armor,Consumable,Weapon}Tags`, falling back to title-cased slug.

**`scripts/trick-magic-daily.js`** (+ `styles/trick-magic-daily.css`) — house rule: Trick Magic Item during daily preparations, tricked items work check-free until the next prep.
- Registered as a pf2e-dailies custom daily on `ready` (`game.dailies.api.registerCustomDailies` — reonZ modules expose APIs at `game.<id minus "pf2e-", camelCased>.api`, like `game.toolbelt`, **not** on the module object); condition-based (feat slug `trick-magic-item` + ≥1 trickable item), so no compendium UUIDs involved. Row slugs are item ids; `save: true` persists skill picks; `empty: true` = skip.
- "Trickable" mirrors the system gate in `consumable/document.ts`: category wand/scroll/spell-gem with `system.spell` that fails `actor.spellcasting.canCastConsumable`. Skills/DC mirror `calculateTrickMagicItemCheckDC` (tradition traits → skill, level-based DC; reuses `levelBasedDC` from `expressions-inserter.js` + a world-setting adjustment).
- Success mechanism: `canCastConsumable` passes if any **prepared/spontaneous** entry `canCast` the spell (innate is explicitly excluded when an origin item is involved; match is `tradition || spell in list`). So success adds a temp 0-slot **spontaneous** entry (`proficiencySlug` = the skill) + spell copies wired in via the `flags.pf2e-dailies.identifier` mechanism (same as its Staves daily). dailies auto-deletes temp items at next rest; our `rest` callback clears `flags.pf2e-house-rules.tricked` on items. `process` wipes stale entries/flags first, so re-prepping never stacks.
- Known leak (documented in README): while an entry exists, *any* consumable of that tradition casts check-free — the system gates per entry, not per item. Strict per-item gating would need an empty-tradition entry (match falls through to spell-list slug) — untested, revisit if needed.

**`scripts/region-teleport-follow.js`** — GM hotkey (J) to "follow" a region's Teleport Token or Change Scene Level behavior: view the destination scene/level + pan.
- v14 teleport behavior schema: `destinations` is a **SetField of Region UUIDs** (+ `choice` flag) — v12's single `destination` field is gone. Behavior type key is `teleportToken`; skip `disabled` behaviors.
- `changeLevel` behaviors have **no destination config**: destinations are the region's `levels` Set of level ids (empty = all scene levels) minus the current one — mirror core's `ChangeLevelRegionBehaviorType.#getDestinationLevels`, but "current" here is `canvas.level` (the viewed level), not a token's. Switch view with `scene.view({level: id})` (works on the already-viewed scene); compute the pan center from the source region *before* the await, since the redraw destroys placeables. Both destination kinds share one picker dialog.
- Under-cursor matching must filter sources by `regionDoc.includedInLevel(canvas.level.id)` (public on all canvas docs; empty `levels` set = true): stair regions of different floors stack at the same x/y, and matching invisible floors' regions forces a needless picker.
- Teleport destinations must also honor the destination region's `levels` restriction: multi-level scenes are often stitched with **same-scene teleports between floors** (that's how our worlds are built — zero changeLevel behaviors, 168 teleports), where no scene switch happens but the viewed level must change or the follow silently no-ops. Scene + level switch in one `scene.view({level})` call.
- Region under cursor off the Regions layer: `canvas.mousePosition` + `RegionDocument#testPoint(ElevatedPoint)`. testPoint is 3D — clamp the test elevation into the region's own `elevation.bottom/top` range (null = ±∞) or elevation-banded regions never match.
- Navigation is view-only (`scene.view()`, never activate) so players are untouched. Center prefers the drawn placeable (`regionDoc.object.center`) and falls back to a bbox over `regionDoc.shapes` data, since the placeable may not exist right after a scene switch.

**`scripts/scene-levels-composer.js`** — combine single-floor scenes into one v14 multi-level scene + Stair Painter (system-agnostic; guard is `foundry.documents.Level`).
- v14 Levels schema (verified in server source `~/foundry` on euclid): Levels are embedded docs (`Scene#levels`); every scene gets a default level (`"defaultLevel0000"`) holding its art, so source art lives at `scene.initialLevel` — always generate fresh level ids when combining. Placeables carry `levels: SceneLevelsSetField` (empty Set = **all** levels); tokens carry a singular `level` id. `Scene.create` keeps embedded `_id`s by default (`keepEmbeddedIds`), so placeables can reference pre-generated level ids in one create call; the scene's own id is pre-generated with `keepId: true` so intra-scene UUIDs inside region behavior data (teleports) get rewritten to the new scene.
- Level art renders anchored at `sceneRect.center + textures.offset`, fitted to the scene rect then × `scaleX/Y` (PrimaryCanvasGroup#drawLevelTexture). Composer uses `fit: "fill"` with `scale = k·srcRect/targetRect` (k = grid-size ratio) so any image size keeps its source rendering scale; placeables translate by the rect-center delta, snapped to the grid, with per-floor manual offsets applied unsnapped on top.
- Elevation `bottom/top: null` means ±∞ **in source data only** — prepared docs convert to `±Infinity`, which fails schema validation if written back. Always read bands via `toObject()`/`_source`.
- `Level.visibility.levels` on the *viewed* level lists which other levels render. A stair = Region with `levels: [a, b]` + a `changeLevel` behavior (no required config); its destination list is the region's levels minus the token's current one.
- Stair Painter captures one drag via `window` capture-phase pointer listeners that `stopPropagation()` before PIXI's canvas-element listeners see them (blocks layer drag-select). `canvas.mousePosition` does NOT update while blocked — coordinates come from `canvas.canvasCoordinatesFromClient`. Preview graphics live on `canvas.controls`; PIXI is 7.4 (classic `lineStyle`/`drawRect` API).

**`scripts/level-alpha-mask.js`** — cut see-through alpha holes into a Level's background/foreground art, drawn on-canvas with live preview (system-agnostic, v14-only).
- Level texture meshes are public: `canvas.primary.levelTextures`, named `Level.<level.index>.<background|foreground>` (from `Scene#_configureLevelTextures`). The array is rebuilt on every canvas draw — resolve meshes by name each use, never hold refs. Live preview = swap `mesh.texture` for a `PIXI.Texture.from(offscreenCanvas)` and call `baseTexture.update()` after recompositing; transparent pixels just reveal lower-level meshes (alphaThreshold only gates occlusion/vision).
- World→image mapping inverts the mesh placement math (anchor at `sceneRect.center + textures.offset`, fit-mode base scale × `scaleX/Y`); needs the image's natural size, so the original is loaded as an `Image` anyway for compositing. Rotated textures are refused.
- Nondestructive model: shapes (image-pixel space) + `originalSrc` + feather + rev live at `flags.pf2e-house-rules.alphaMask.<texKey>` on the Level; Apply composites original + mask (canvas 2D `destination-out`, feather via `ctx.filter = blur()`) and uploads `<base>-masked-<rev>.webp` via `foundry.applications.apps.FilePicker.implementation.upload("data", dir, file)`. The rev counter exists because re-uploading the same filename gets served from stale texture caches; old revisions accumulate (documented in README).

**`scripts/navigation-guard.js`** — neutralize mouse back/forward buttons; confirm real unloads.
- Primary defense is a history-sentinel trap (pushState a dummy entry at load; popstate re-arms it), so mouse-back is a same-document no-op — no unload occurs, so no prompt is involved and browsers can't bypass it. `beforeunload` (`preventDefault` + `returnValue`) is only the backstop for tab close / Ctrl+W / F5, gated behind a client setting (default on) since it fires on every dev-loop F5. The listener reads the setting in a try/catch and fails toward prompting, because unload can happen before `init` registers it.

**`scripts/misc-hooks.js`** — grab-bag for small one-hook automations, one world-scoped enable setting each.
- Auto origin name: `preCreateItem` (fires on the initiating client only) appends the origin actor's name to effects whose name ends with the word "Immunity" (the name test doubles as the double-append guard — an appended `(Name)` no longer ends with Immunity); origin UUID from `system.context.origin.actor`. `fromUuidSync` **throws** on UUIDs needing async retrieval (compendium origins) — caught and treated as no origin; the whole hook body is try/caught because a `preCreate` hook error cancels the creation. Assigned-character fallback is a separate setting, default off.
- Darkness regions: PF2e on v14 places spell areas as **Regions** (no MeasuredTemplate document exists), via `placeRegionFromItem` → `canvas.regions.placeRegion`, stamped with `flags.pf2e.origin` (`slug`, `castRank`, …; slug is injected at pack-build time from the name); bursts are one `circle` shape (`x`, `y`, `radius` in px). The system's lighting only understands darkness as **negative light sources** (`config.negative`; `TokenDocumentPF2e#emitsDarkness`), not the `adjustDarknessLevel` behavior (tried first; it only alters global illumination). So the active GM creates a linked AmbientLight (`flags.pf2e-house-rules.darknessRegion` = region id) in `createRegion`, syncs it in `updateRegion`, and deletes it in `deleteRegion`. AmbientLight create is ASSISTANT+ (default metadata); Region delete is `OWNER`, and PF2e grants the placing user OWNER, so players can dismiss their own. Only GMs may create/update a Region carrying behaviors (`BaseRegion.#canCreate`/`#canUpdate`, server-side) — adding behaviors in a player's `preCreateRegion` gets the whole placement rejected.
- Consumable formula templates: PF2e HUD uses foundry-helpers `consumeItem` (`src/item.ts`), which builds `new DamageRoll("(formula)[type,kind]")` with no roll data; `DamageInstance.parse` then replaces missing `@` refs with `"0"` (the system's `consume()` passes `getRollData()` = actor roll data + `item`). Workaround bakes `flags.world.damageFormulaTemplate` into `system.damage.formula` in `preCreateItem`/`preUpdateItem` (flag scope stays `world` — existing items carry it). No manual flag needed: a formula still containing `@item.level` is adopted as the template (copied to the flag) on create or on the item's next update. `SpecialResource` items go through ordinary embedded create/update (`#createItem` clones the source with `system.level.value` set; daily renewal updates the level), so both hooks fire for them. `preUpdate` `changes` are cleaned + expanded but **not yet diffed**, so a sheet submit always contains `system.level.value` (rebake on every save, idempotent). v14 flag deletions arrive as `ForcedDeletion` objects, not strings — type-check before treating a changed value as a template. `Hooks.#call` catches thrown errors (logged, hook treated as returning undefined).

**`scripts/adventures-plus.js`** — optional rules from the third-party *Adventures+* supplement; one world-scoped enable setting per rule (default on), setting keys prefixed `ap`.
- Initiative nat 20/1: `preCreateChatMessage` (rolling client only). Initiative checks carry `flags.core.initiativeRoll: true` + `flags.pf2e.context.type === "initiative"` (system `check.ts`). The note is appended as `li.roll-note` inside the flavor's `ul.notes` (created if absent) with raw `@UUID[...]` text — core only enriches `content` on render, but `ChatMessagePF2e` enriches `flavor` too, so links resolve. Hero Point rerolls delete + recreate the message with the kept roll first in `rolls`, so the hook re-fires correctly. Settings register immediately if `game.ready` (lets the file be console-`import()`ed into a running game before the manifest restart).

**`scripts/counteract.js`** (+ `styles/counteract.css`) — counteract-check dialog: infers modifier/rank/DC/target rank with a "why", previews outcomes, rolls via the system pipeline.
- Every spellcasting entry exposes `entry.counteraction` (a `Statistic` from `createCounteractStatistic`: attribute + proficiency only, plus `counteract`-selector bonuses; NPCs reuse the entry's base modifier). That is the rules-correct counteract modifier, not the spell attack. `actor.getStatistic("counteract")` picks the best entry but **throws on non-casters** (empty `reduce` without initial value) — build the list from `actor.spellcasting.contents` instead. Innate entries already resolve Cha + max(trained, best spell proficiency).
- `Statistic#check.roll({ dc, extraRollNotes, extraRollOptions, target, item, token, skipDialog })` — with a DC the system computes the degree and filters notes by `outcome`; DC/result visibility follows the metagame settings (`opposingActor.hasPlayerOwner || dc.visible || metagame.dcs`). Notes may be plain `RollNoteSource` objects; `visibility: "gm"` hides one from players. `Statistic` isn't on `game.pf2e` — reach the class via `actor.perception.constructor` for ad-hoc (custom-modifier) statistics.
- Target inference: effect items carry `system.context.origin.{actor,item,token}` UUIDs (actor may be a `Scene…Token…Actor` UUID — resolve via the token), `system.level.value`, `system.fromSpell`; afflictions carry `system.save.value`. Spell cast messages carry `flags.pf2e.origin = { type: "spell", uuid, castRank, rollOptions }` (`rollOptions` includes `origin:action:slug:cast-a-spell` for real casts). "DC from the target" (its `spell-dc` statistic) is the robust default; a chosen effect only refines the rank.
- Remove/Restore: `check.roll({ callback })` receives `(roll, outcome, message)`; the roller tags the message (`flags.pf2e-house-rules.counteract`: effect/bearer UUIDs, ranks, outcome) — authors may update their own messages. Removal stores `effect.toObject()` under `…counteract.removed` and Restore recreates it with `keepId: true` (so the stored effect UUID stays valid). Non-permitted users relay `{ type: "counteract", action, messageId }` over `module.pf2e-house-rules`; the set-targets listener on the same channel ignores typed payloads.
- Effects panel hover card = a **locked core tooltip**: `#tooltip`'s children are moved (listeners intact) into a new `aside.locked-tooltip` with the system's `cssClass` (`pf2e effect-info application`) appended to `<body>`; the effect UUID sits on `.content[data-item-uuid]`. A body `MutationObserver` is the hook. Character/NPC sheets are AppV1 → header buttons via `get<ClassName>HeaderButtons` (`CharacterSheetPF2e`, `NPCSheetPF2e`, `SimpleNPCSheet`).

## Adding a tweak

New file in `scripts/`, add it to `esmodules` in `module.json`, document it in `README.md`. Guard for missing dependencies so the module stays safe to run regardless of what's installed.
